MUIO / OSeMOSYS Version History

ver 5.7.02026-09-30
  • Func Added a Balance Level setting per commodity (Timeslice / Season / Annual), controlling the time resolution at which each commodity's energy balance is enforced.
  • Code Model file updated to support commodity balance levels: added SeasonalRateOfActivity and related constraints for season‑resolution technologies; commodity/technology subsets by balance level are now supplied directly from the data file.
  • Bug Fixed the seasonal capacity constraint (CAa4_S_Constraint_Capacity) to use SeasonalRateOfActivity instead of raw activity summed over the season's timeslices, consistent with the commodity balance level feature.
  • Tech Added a backend log warning (app.log) for the storage‑aware model variant: flags technologies that are linked to storage but have no Timeslice‑balanced commodity, since they are forced to Timeslice resolution regardless of their commodities' Balance Level. Diagnostic only, not shown in the UI.
  • Func Added new parameter Operation Profile [R,T,Y,Ts] (RYTTs group, same shape as Capacity Factor).
  • Code Model file updated to include a new constraint enforcing Operation Profile.
  • Bug Fixed an issue where manually edited constraint names were not always persisted and could revert to the automatically generated default name after saving.
  • Bug Fixed data file generation for parameter groups with per‑timeslice data (e.g. Capacity Factor, Operation Profile): when a group contained more than one parameter, the generated data file was missing a terminator between them, causing values from different parameters to be merged incorrectly.
  • Func Added new annual (non‑timeslice) variables Production By Technology By Mode and Use By Technology By Mode [R,T,M,F,Y]. The existing per‑timeslice versions are still available, renamed to Production/Use By Technology By Mode - Ts [R,L,T,M,F,Y].
  • Bug Fixed results view generation for the new annual By‑Mode variables: a required grouping (by Technology, Commodity, Mode) was missing, so their result views were not being generated.
  • Func Results parameter selector (Pivot page) now supports type‑to‑search filtering and groups the list into Variables, Indicators, and Duals, instead of one long unsorted list.
ver 5.6.02026-03-31
  • Func Fully implemented and tested indicator framework with user‑defined technology categorization and transparent, recorded indicator formulas (OSeMOSYS variables and parameters), enabling consistent cross‑scenario reporting.
  • Func Implemented in‑interface display of concise explanations and definitions for OSeMOSYS variables, parameters, and sets within MUIO, improving user understanding and reducing ambiguity.
  • Disp Redesign of Case run page.
ver 5.5.02026-02-28
  • Func User toggled scenario checkbox selection — all scenarios set to: [checked/un-checked].
  • Func Model cleanup mechanism improved to remove corrupted/invalid data and restore consistent analysis state.
  • Func Persisted view definition during cleanup to maintain user‑defined visualization settings.
  • Func Added on‑demand model file viewer in a modal window (syntax highlighting + lazy loading).
  • Tech Restructured Python solver runner for clearer stages (preprocess → LP → solve → postprocess) and stronger error handling.
  • Tech Unified cross‑platform solver handling: detects bundled GLPK/CBC (Win/macOS/Linux) and falls back to system solvers when needed.
  • Tech Improved backend logging: automatic creation of clean app.log for diagnostics.
  • Bug Fixed the dynamic unit‑assignment script that resolves units based on Technology–Commodity rules, ensuring variables now receive correct units automatically.
  • Tech Electron startup guard: the app now waits for the backend server to be reachable before showing the UI (async fetch with 30× retries @ 500 ms).
    • Prevents “blank window / server not up yet” race
    • Logs version line at startup
    • Retry behavior configurable via environment (e.g., MUIO_SERVER_URL, MUIO_SERVER_RETRIES, MUIO_SERVER_DELAY_MS)
